Security Review Report — F-082: Label Open Access and Label Search

Reviewer: Claude Code (AI)  |  Date: 2026-09-24  |  Standard: OWASP Top 10 + OWASP API Security Top 10

Feature Scope for Security Review

This feature makes three targeted changes: (1) adds a labels: { has } arm to an existing Prisma findMany search filter; (2) removes a frontend-only conditional render on two label action buttons in the work item edit modal; (3) adds a label tag input to the create work item modal. No new endpoints, no new data models, and no new auth paths are introduced.

OWASP Web Top 10

RiskApplicableStatusNotes
A01 — Broken Access ControlYesPASSThe frontend restriction on label add/remove is a UI convenience gate, not a security boundary. The backend PATCH /work-items/:id endpoint has always accepted labels from any authenticated project member. Backend authorization (JwtAuthGuard + ProjectRoleGuard) is unchanged. Removing the UI gate does not open any new backend attack surface.
A02 — Cryptographic FailuresNoN/ANo new data storage or token handling.
A03 — InjectionYesPASSThe label search value is passed to Prisma's labels: { has: filters.search }. Prisma parameterises all inputs — no raw SQL string concatenation. The label value entered in the create/edit UI is a plain string stored via Prisma's parameterised update — no injection surface. XSS: labels are rendered as React text nodes (not dangerouslySetInnerHTML), so stored label strings cannot inject HTML.
A04 — Insecure DesignNoN/ANo new business flow or privilege model change. All project members could already update labels via the API — this just exposes the existing capability in the UI.
A05 — Security MisconfigurationNoN/ANo configuration, CORS, or header changes.
A06 — Vulnerable & Outdated ComponentsNoN/ANo new dependencies.
A07 — Identification & Authentication FailuresNoN/ANo auth flow changes.
A08 — Software & Data Integrity FailuresNoN/ANo new build artefacts or supply chain changes.
A09 — Security Logging & MonitoringYesPASSThe existing label_added / label_removed audit log entries continue to be written for all label changes regardless of the role performing the action. Monitoring coverage is preserved.
A10 — SSRFNoN/ANo outbound HTTP calls.

Verdict: Cleared
